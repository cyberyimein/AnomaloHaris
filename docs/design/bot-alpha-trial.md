## 试用顺序

1. 进入顶部 Bot 页，在设置中确认模型、时区和每日 token 额度，然后选择启用。
2. 进行一次普通对话，要求记住一个可核查的偏好；在记忆页确认内容与来源。
3. 建立几分钟后的一次性任务，关闭页面后再回来检查执行记录和后台结果。
4. 设置一个低频定期任务，观察多个周期是否正常执行、失败信息是否足够清楚。
5. 测试停止执行与检查点继续；确认旧执行记录和新执行记录可以区分。
6. 对话积累后手动压缩，核对早期约束能否继续影响回答；出现遗忘时保留对应会话与 Run ID。

反馈建议记录：期望行为、实际行为、发生时间与时区、任务／Run ID、是否重启或休眠、截图。不要在反馈中粘贴 API key。

## 第一版边界

Host 必须保持运行；关机或休眠期间不会执行任务，恢复后按错过调度规则处理。关闭网页不会停止已接受的执行。失败／中断任务需要显式恢复，不承诺任意工具副作用恰好执行一次。

已有真实模型验证是小规模功能验证，尚未完成多日连续运行验证。token 额度不等于精确费用上限。摘要质量、记忆召回质量以及结果提示是否好用，需要在实际使用中评估。

暂不包含外部消息通知、后台记忆整合、向量检索、任意 cron、完整历史擦除。下一阶段优先根据试用暴露的问题排序，不必先引入新的部署基础设施。
